### Notes
- First release of `@codat/sync-for-payables` generated by Codat's own SDK pipeline rather than Speakeasy. The client class, method names, parameters and model type names match v9.3.2, so ordinary use needs no code change.
- Breaking: a path into the package no longer resolves. v9.3.2 put its compiled JavaScript at the package root mirroring `src/` and declared no `exports` field, so `@codat/sync-for-payables/sdk/models/shared/company.js` worked. This release compiles to `dist/` and names the paths it exports: the package root, `sdk/models/shared`, `sdk/models/operations`, `sdk/models/errors`, `sdk/types`, `core.js`, `lib/http`, `funcs/*.js` and `package.json`.
- Model types come from the package root now, so `import { Company } from "@codat/sync-for-payables"` replaces the old path. v9.3.2 exported no models from the root, which is why reaching inside the package was the only way to get at them.
- The `zod` validation schemas that sat beside those types are gone, and `zod` is no longer a dependency. In place of v9.3.2's `Company$inboundSchema` and `companyFromJSON`, each model exports `CompanyFromJSON`, `CompanyToJSON` and `instanceOfCompany`.
- `SDKError.message` now holds only the message itself. v9.3.2 appended the status code, the content type and the response body to it. All three are still on the error, as `statusCode`, `contentType` and `body`.
- Requests and parsed responses were compared against v9.3.2 across 31 requests and 25 responses, and they match. On every request this build sends a `user-agent` naming Codat's generator instead of Speakeasy's, no empty `cookie` header, and query parameters can come out in a different order.
